# Audit, November 2026: what was checked, what was broken, what was fixed

17 Nov 2026. The bug hunted for: a feature that silently shows n/a, empty, stale or wrong data in
real use (after the close, at weekends, during a provider outage, on Streamlit Cloud's UTC clock)
while the tests pass. The trigger was the Research Notes "app score n/a" bug fixed in #364.

## How it was checked

- Every page 02–15, every view, the alert jobs (`alerts/`), the workflows, `scripts/` and
  `trade_store.py`. Each data path was traced from the writer (warm jobs, alert jobs, KV keys and
  their `user_id`) to the reader (freshness rules, ticker format, IST vs UTC, empty state).
- Every fixed bug has a test that fails on the old code and passes on the new one.
- Every PR ran the full suite (`pytest -m "not slow"`) and the page smoke tests.
- `verdict-regression-reviewer` ran on the fundamentals / thesis change: no posture or confidence
  changed.
- Not in scope: Command Centre (page 01, another session was editing it). Research Notes was left to
  #364.

**Status words used below:**
- **Fixed #N**: bug reproduced in a test and fixed in that PR.
- **No bug found**: code read end to end, tests exercise it; NOT run against live data.
- **Not verified**: needs live NSE / Yahoo / Angel One / a broker login, so it could not be
  exercised here.
- **Open**: a real issue that is not fixed yet; the reason is given.

Nothing below is marked "works" on the strength of having been looked at.
